## CLI Commands

```bash
# Badges
sklab badge ./my-skill --output badge.svg

# History
sklab history ./my-skill
sklab compare ./my-skill --from v1.2.0 --to v1.3.0

# Benchmarks
sklab benchmark ./my-skill --category react-scaffolding
sklab leaderboard --category react-scaffolding

# Publishing
sklab publish ./my-skill --marketplace skillsmp.com

# CI/CD gates
sklab evaluate ./my-skill --min-score 80 --fail-on-regression
```

## XDG Base Directory Migration

Migrate from `~/.sklab/` to XDG-compliant paths, separating config, data, and cache:

| Current | XDG Path | Env Override | Purpose |
|---------|----------|-------------|---------|
| `~/.sklab/config.json` | `~/.config/sklab/config.json` | `$XDG_CONFIG_HOME` | UUID, preferences, analytics opt-in |
| `~/.sklab/telemetry.db` | `~/.local/share/sklab/telemetry.db` | `$XDG_DATA_HOME` | SQLite telemetry data |
| (in config.json) | `~/.cache/sklab/` | `$XDG_CACHE_HOME` | PyPI version check cache |

### Implementation Details

- Update `core/constants.py` to resolve paths via `$XDG_CONFIG_HOME` / `$XDG_DATA_HOME` / `$XDG_CACHE_HOME` with `~/.config/`, `~/.local/share/`, `~/.cache/` fallbacks
- Auto-migrate: on first run, if `~/.sklab/` exists and XDG paths don't, move files to new locations
- Preserve `install_uuid` across migration (must not change)
- Project-local `.sklab/` stays unchanged — only global state moves
- Reference: `gh` CLI follows this pattern (`~/.config/gh/`, `~/.local/share/gh/`)

### Competitive Context

- Tessl uses `~/.tessl/` (no XDG) — this is a differentiation opportunity
- npm, Docker, AWS CLI also skip XDG — but modern tools (gh, Helm, neovim, mise) adopt it
- XDG is Linux-native but works on macOS for CLI tools (not `~/Library/` which is for GUI apps)
