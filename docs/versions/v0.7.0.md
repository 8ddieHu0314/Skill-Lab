# v0.7.0: LLM-as-Judge, Multi-Provider LLM, Per-Skill Config & Enhanced Static Checks

**Status:** In Progress

## Overview

Adds LLM-as-judge quality review to `sklab evaluate` (8-criterion rubric across Activation Quality and Instruction Quality axes), multi-provider LLM support (OpenAI, Gemini alongside Anthropic), per-skill `.sklab/config.yaml` for persistent preferences and evaluation snapshots, `.env` file support, and 4 new static checks from competitive gap analysis and spec alignment — bringing the total from 33 to 37 checks.

## Changes Since v0.6.0

### 1. LLM-as-Judge Quality Review (PR #15)

`sklab evaluate` now includes LLM-powered quality assessment alongside static checks. When an API key is available, the skill is scored on 8 criteria across two axes using a structured rubric grounded in the [Agent Skills Spec](https://agentskills.io).

**Activation Quality** (Description) — will the agent find and activate this skill?

| Criterion | What it judges |
|-----------|---------------|
| Intent Clarity | User intent framing vs implementation details |
| Trigger Coverage | Natural language variations, indirect requests |
| Scope Precision | Not too broad, not too narrow |
| Distinctiveness | Differentiation from base agent capabilities |

**Instruction Quality** (Body) — will the agent produce good output following these instructions?

| Criterion | What it judges |
|-----------|---------------|
| Domain Expertise | Real specific knowledge vs generic filler |
| Cognitive Efficiency | Adds what agent lacks, omits what it knows |
| Procedural Clarity | Actionable steps vs vague declarations |
| Error Resilience | Gotchas, failure modes, recovery guidance |

- Each criterion scored 0-4, normalized to 0-100% per axis
- Judge Score = average of both axes
- Verdict bands: 90+ Excellent, 75-89 Good, 50-74 Needs work, <50 Poor
- Graceful degradation: static results always shown; LLM review runs if API key present
- `--skip-review` flag for static-only evaluation (CI, offline, cost-conscious)
- `--model` flag for provider/model selection (same resolution chain as generate/optimize)
- Results persisted to `.sklab/config.yaml` as `last-review`
- New module: `judge/judge.py` (SkillJudge) + `judge/rubric.md` (system prompt)
- New data models: `JudgeCriterion`, `JudgeResult` in `core/models.py`

```bash
sklab evaluate ./my-skill                     # Static + LLM review
sklab evaluate ./my-skill --skip-review       # Static only
sklab evaluate ./my-skill --model gpt-4o      # Use OpenAI for review
```

### 2. Multi-Provider LLM Support (PR #12)

`sklab generate` and `sklab optimize` now support OpenAI and Gemini models in addition to Anthropic.

| Provider | Model prefix | API key env var |
|----------|-------------|-----------------|
| Anthropic | `claude-*` (default) | `ANTHROPIC_API_KEY` |
| OpenAI | `gpt-*`, `o3-*` | `OPENAI_API_KEY` |
| Gemini | `gemini-*` | `GEMINI_API_KEY` |

- `LLMProvider` Protocol abstraction in `core/llm.py` with `AnthropicProvider`, `OpenAIProvider`, `GeminiProvider`
- Provider auto-detected from model ID prefix
- `_PRICING` dict tracks per-model token costs for all three providers
- `anthropic`, `openai`, and `google-generativeai` are all required dependencies

```bash
sklab generate ./my-skill --model gpt-4o
sklab optimize ./my-skill --model gemini-2.0-flash
```

### 3. `.env` File Support (PR #12)

- `python-dotenv` loads `.env` from CWD at CLI startup
- Real env vars override `.env` values (`override=False`)
- Entry point is `cli:main` (not `cli:app`) so dotenv loads before Typer dispatch

### 4. Per-Skill Config `.sklab/config.yaml` (PR #13)

Auto-created config file for per-skill persistent state. Never required — all commands work without it.

```yaml
# .sklab/config.yaml
version: 0.1.0

llm:
  model: claude-haiku-4-5-20251001

last-evaluate:
  score: 82.5
  checks-passed: 31
  checks-total: 37
  date: "2026-03-26T03:18:24Z"
```

- **Model resolution chain**: `--model` flag > config model > `SKLAB_MODEL` env > default
- `evaluate` snapshots score/checks/date after each run
- `generate` and `optimize` persist the resolved model
- `trigger` ensures config exists
- Corrupt/missing config gracefully falls back to defaults

New module: `core/skill_config.py` with `SkillConfig`, `LastEvaluate` dataclasses, `load_config()`, `save_config()`, `update_evaluate()`, `update_model()`, `resolve_model()`

### 5. Enhanced Static Checks (PR #14)

4 new checks from tessl competitive gap analysis and agent skills spec alignment:

| Check ID | Dimension | Severity | What it catches |
|----------|-----------|----------|-----------------|
| `content.broken-internal-links` | CONTENT | MEDIUM | Markdown links `[text](path)` to nonexistent files |
| `structure.files-outside-spec-dirs` | STRUCTURE | LOW | Top-level files/dirs not in `references/`, `assets/`, `scripts/`, `evals/` |
| `content.orphaned-files` | CONTENT | LOW | Files in spec dirs not referenced from SKILL.md (with transitive resolution) |
| `structure.scripts-help-support` | STRUCTURE | LOW | Scripts without `--help` support (argparse, click, getopts, etc.) |

**Check count: 33 → 37** (structure: 11→13, content: 11→13)

### 6. Spec Alignment Fixes (PR #14)

- `.go` added to `VALID_SCRIPT_EXTENSIONS` (Go scripts documented in spec)
- `evals/` added to recognized spec directories (structured eval format from agentskills.io)

### 7. Token Cost Breakdown in `sklab info` (PR #14)

`sklab info` now shows front-loaded vs on-demand token costs:

```
Tokens (estimated):
  Discovery:    ~135 tokens (name + description)
  Front-loaded: ~1207 tokens (full SKILL.md)
  On-demand:    ~6858 tokens (references + assets + scripts)
  Total:        ~8065 tokens
```
