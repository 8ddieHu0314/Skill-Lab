# v0.5.0: Telemetry, Stats & CLI Refactor

**Status:** Released

## Overview

Adds anonymous usage telemetry with full privacy controls, a `sklab stats` command for usage insights, automatic skill invocation tracking via `sklab setup`, and a modular CLI architecture. Also renames severity levels from ERROR/WARNING/INFO to HIGH/MEDIUM/LOW for semantic clarity.

## Changes

### 1. Anonymous usage telemetry

Opt-out analytics that collect command usage, runtime duration, exit codes, OS/Python version, and evaluation scores. Designed with privacy as a first-class concern.

**How it works:**

- Events are recorded to a local SQLite database (`~/.sklab/usage.db`) with 4 normalized tables: `installs`, `command_events`, `skill_events`, `error_events`
- Each event is synced inline via fire-and-forget POST to `https://api.skill-lab.dev/v1/events` (2s timeout, failures silently swallowed)
- A `@_with_telemetry(command_name)` decorator wraps all CLI commands for consistent timing and event recording

**Privacy controls:**

- Opt-out via `SKLAB_NO_ANALYTICS=1` or `DO_NOT_TRACK=1` environment variables
- Automatically disabled in CI environments (GitHub Actions, GitLab CI, Travis, CircleCI, Jenkins, Buildkite, Azure Pipelines, Bitbucket) and non-interactive contexts
- Local-only fields (`skill_path`, `skill_version`, `skill_source`) are never synced
- Only flag names collected, never values; only error types, never messages
- Local retention: 90 days; server retention: 12 months
- Notice shown on first interactive run

**CLI management:**

```bash
sklab telemetry status             # Show enabled/disabled, DB path, row counts
sklab telemetry enable             # Opt in
sklab telemetry disable            # Opt out
sklab telemetry show [-n N] [--json]  # View recent events
```

**Debug mode:** Set `SKLAB_TELEMETRY_DEBUG=1` to print exact JSON payloads to stderr without making the POST.

**Files:** `core/telemetry.py`, `commands/telemetry.py`, `docs/PRIVACY.md`, `docs/DEV_STATS.md`

### 2. `sklab stats` — usage statistics

Rich-formatted tables showing evaluation history, scores, and token usage. Queries the local telemetry database.

```bash
sklab stats                # Overview: invocations, avg scores, total tokens, version history
sklab stats count          # Skill name | invocation count | tokens used (current month)
sklab stats score          # Skill name | current score | baseline score | change
sklab stats tokens         # Skill name | tokens/invocation | total tokens (current month)
sklab stats --here         # Limit to skills in current git repo
```

Tracks baseline scores (first evaluation) vs current scores (latest evaluation) with delta. Marks skills as "new" if only one evaluation exists.

**Files:** `core/stats.py`, `reporters/stats_reporter.py`, `commands/stats.py`

### 3. `sklab setup` — skill invocation tracking

One-time hook configuration for automatic skill tracking in Claude Code and Cursor.

```bash
sklab setup                # Configure PostToolUse hooks for skill tracking
```

- Writes hooks to `~/.claude/settings.json` (Claude Code) and `~/.cursor/hooks.json` (Cursor)
- Safe to run multiple times (idempotent)
- Hidden `sklab _track-invocation` command reads hook data from stdin and records skill invocations with token counts

**Files:** `core/setup.py`, `commands/setup.py`

### 4. CLI refactor — `commands/` package

Split monolithic `cli.py` into a modular `commands/` package:

| Module | Commands |
|--------|----------|
| `commands/evaluate.py` | `evaluate`, `validate`, `list-checks` |
| `commands/trigger.py` | `trigger` |
| `commands/generate.py` | `generate` |
| `commands/info.py` | `info`, `prompt`, `eval-trace` |
| `commands/stats.py` | `stats`, `stats count`, `stats score`, `stats tokens` |
| `commands/telemetry.py` | `telemetry status`, `enable`, `disable`, `show` |
| `commands/setup.py` | `setup`, `_track-invocation` |

Shared helpers (`_resolve_skill_path()`, `_cli_error_handler()`, `_with_telemetry()`) remain in `cli.py`.

### 5. Severity rename: ERROR/WARNING/INFO → HIGH/MEDIUM/LOW

Renamed for semantic clarity — "high/medium/low severity" is more intuitive than overloaded "error/warning/info" which are easily confused with log levels.

| Before | After | Weight | Icon | Color |
|--------|-------|--------|------|-------|
| `ERROR` | `HIGH` | 1.0 | X | bold red |
| `WARNING` | `MEDIUM` | 0.5 | ! | yellow |
| `INFO` | `LOW` | 0.25 | i | blue |

Scoring weights unchanged. Updated across all checks, tests, and documentation.

**Files:** `core/models.py`, all check modules, `reporters/console_reporter.py`

### 6. PyPI version checking

Runs once per day on any command (2s timeout, cached). If a newer version is available, prints a notice to stderr:

```
sklab X.X.X is available (you have Y.Y.Y). Run: pip install --upgrade skill-lab
```

Runs regardless of analytics opt-in status.

### 7. Code quality improvements

- **Test consolidation:** Replaced repetitive test methods with `@pytest.mark.parametrize` for better coverage with less code
- **Code deduplication:** Extracted shared patterns across runtimes, checks, and reporters
- **SSL verification:** Uses `certifi` for SSL certificate verification in telemetry POSTs and PyPI version checks
- **Windows compatibility:** Close SQLite connections immediately after write to release file locks
