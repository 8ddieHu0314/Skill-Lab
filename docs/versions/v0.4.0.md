# v0.4.0: Spec Parity & Correctness Improvements

**Status:** Released

## Overview

Closes 4 gaps between Skill-Lab and `skills-ref` (Anthropic's official reference implementation), making Skill-Lab a strict superset of `skills-ref`. Adds `sklab info` and `sklab prompt` commands, NFKC Unicode normalization for name matching, and a custom YAML loader that prevents implicit type coercion.

## Changes

### 1. NFKC Unicode normalization for naming check

`NameMatchesDirectoryCheck` now normalizes both sides with `unicodedata.normalize("NFKC", ...)` before comparison, so precomposed and decomposed Unicode forms correctly match (e.g., `cafe\u0301` vs `caf\u00e9`).

**Files:** `checks/static/naming.py`

### 2. `sklab info` — skill metadata inspector

Rich-formatted panel showing metadata, structure, body line count, and token cost estimates. Replaces and improves on `skills-ref`'s `read-properties`.

```bash
sklab info ./my-skill              # Rich panel
sklab info ./my-skill --json       # JSON output
sklab info ./my-skill --field name # Single field extraction
```

Token estimation uses a `len(text) // 4` heuristic (no external dependency). Reports both **discovery cost** (name + description) and **activation cost** (full SKILL.md).

**Files:** `cli.py`, `core/tokens.py`

### 3. `sklab prompt` — multi-format prompt export

Exports one or more skills as a prompt for agent platforms. Replaces and improves on `skills-ref`'s `to-prompt` with multiple output formats.

```bash
sklab prompt ./skill-a ./skill-b           # XML (default)
sklab prompt ./my-skill -f markdown        # Markdown
sklab prompt ./my-skill -f json            # JSON
```

Output goes to stdout for piping. Token estimate summary goes to stderr.

**Files:** `cli.py`, `exporters/__init__.py`, `exporters/prompt_exporter.py`

### 4. Custom YAML loader (prevent implicit type coercion)

`_SkillYAMLLoader` subclass of `yaml.SafeLoader` removes implicit resolvers for `tag:yaml.org,2002:bool` and `tag:yaml.org,2002:null`. Values like `yes`, `no`, `true`, `false`, `on`, `off`, `null` remain as plain strings. Empty YAML values become `""` instead of `None`. Numbers still parse normally. Zero new dependencies.

**Files:** `parsers/skill_parser.py`
