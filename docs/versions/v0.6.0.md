# v0.6.0: Security Checks

**Status:** Released

## Overview

Expand the security dimension from a single composite check (`security.scan`) into multiple granular, independently scored checks. Currently all 5 layers are bundled into one check that returns BLOCK/SUS/ALLOW — this version breaks them out so each layer contributes individually to the security score and provides actionable per-check feedback.

## Current State (v0.5.0)

- **1 check**: `security.scan` — a monolithic composite that runs all 5 layers internally
- **Security dimension weight**: 0% (gate check only, not scored)
- **Layers**: A (size/structure), B (unicode/obfuscation), C (YAML allowlist), D (prompt injection), E (evaluator manipulation)
- All findings are bundled into a single pass/fail result

## Goals

1. **Granular checks** — break the 5 layers into individual registered checks so each has its own check_id, severity, and pass/fail status
2. **Security as a scored dimension** — give the security dimension a non-zero weight in the overall score
3. **Better reporting** — each security check shows its own finding details, fix suggestions, and severity
4. **Extensibility** — new security patterns can be added as individual checks without modifying the monolithic scanner

## Proposed Checks

| Check ID | Layer | Severity | What it catches |
|----------|-------|----------|----------------|
| `security.size-structure` | A | MEDIUM | Body >100KB, long lines, repeated tokens, excessive whitespace |
| `security.unicode-obfuscation` | B | HIGH | Invisible/bidi chars near risky keywords, homoglyph words |
| `security.yaml-allowlist` | C | HIGH | Unknown frontmatter keys, malformed field values |
| `security.prompt-injection` | D | HIGH | Instruction override, identity override, safety bypass patterns |
| `security.evaluator-manipulation` | E | HIGH | Score manipulation, pass coercion, issue suppression |

### Backward Compatibility

- Keep `sklab scan` working as-is — it aggregates all security checks and returns BLOCK/SUS/ALLOW
- The existing `SecurityScanCheck` class can become a thin orchestrator over the new individual checks, or be replaced entirely
- `sklab validate` behavior unchanged — BLOCK still fails validation

## CLI Changes

```bash
# Existing (unchanged)
sklab scan ./my-skill              # Still shows BLOCK/SUS/ALLOW with findings table

# New behavior in evaluate/validate
sklab evaluate ./my-skill          # Security checks now appear individually in results
sklab evaluate ./my-skill -V       # Verbose shows each security check pass/fail
sklab list-checks                  # Security checks listed individually
```

## Scoring Changes

- Add security dimension to `DIMENSION_WEIGHTS` in `scoring.py` (e.g. 10-15% weight)
- Rebalance other dimensions accordingly
- `security.size-structure` (Layer A) stays MEDIUM — SUS, not BLOCK
- Layers B–E stay HIGH — these are BLOCK-level findings

## Architecture

```
src/skill_lab/checks/static/security.py
├── SecuritySizeCheck          # Layer A — size/structure anomalies
├── SecurityUnicodeCheck       # Layer B — unicode obfuscation + homoglyphs
├── SecurityYamlCheck          # Layer C — YAML allowlist + field validation
├── SecurityInjectionCheck     # Layer D — prompt injection / jailbreak
├── SecurityEvaluatorCheck     # Layer E — evaluator manipulation
└── (shared helpers)           # _line_of, _match_patterns, Finding, etc.
```

The existing layer functions (`_check_size`, `_check_unicode`, `_check_yaml`, `_check_injection`, `_check_evaluator`) become the `run()` implementations of their respective check classes. Shared helpers remain module-level.

## Telemetry: Non-blocking Sync

The inline `_post_event()` call adds ~200ms latency to every command (up to 2s on timeout). Move the POST to a non-blocking thread so the CLI feels instant again.

**Current:** `_inline_sync()` calls `_post_event()` synchronously, blocking until the HTTP response arrives.

**Proposed:** Fire the POST in a thread without joining. The thread gets ~200ms to complete before the process exits naturally. If it doesn't finish, the existing `_retry_stale_events()` daemon picks it up on the next run.

**Tradeoff:** Slightly lower first-attempt delivery rate (fast commands may exit before the thread completes), but the retry mechanism already handles this. QA showed 100% eventual delivery via retries.

## Project Directory Rename: `.skill-lab/` → `.sklab/`

Rename the project-local artifact directory from `.skill-lab/` to `.sklab/` for consistency with the CLI name and branding.

| Before (v0.5.0) | After (v0.6.0) |
|------------------|----------------|
| `.skill-lab/tests/` | `.sklab/tests/` |
| `.skill-lab/traces/` | `.sklab/traces/` |

This is a **breaking change** — existing `.skill-lab/` directories must be renamed manually.

The global config directory (`~/.sklab/`) is unchanged.
