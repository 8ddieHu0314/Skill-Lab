# v0.6.0: Granular Security, LLM Optimizer & CLI Polish

**Status:** Released

## Overview

Introduces a 5-layer security scanning system with per-check feedback, adds `sklab optimize` for LLM-powered SKILL.md improvement, renames `sklab validate` to `sklab check`, renames the `.skill-lab/` project directory to `.sklab/`, and moves telemetry sync to a non-blocking daemon thread.

## Breaking Changes

- **`.skill-lab/` → `.sklab/`** — project-local artifact directory renamed. Existing `.skill-lab/` directories must be renamed manually.
- **`sklab validate` → `sklab check`** — the quick pass/fail command has been renamed for consistency.
- **`anthropic` is now a required dependency** — previously optional, now needed for `generate` and `optimize` commands.

## Changes

### 1. Security scanning (`sklab scan`)

Introduces a 5-layer security scanning system. Each layer is an individually registered check with its own check_id, severity, pass/fail status, and fix suggestions.

| Check ID | Layer | Severity | What it catches |
|----------|-------|----------|-----------------|
| `security.size` | A | MEDIUM | Body >100KB, long lines, repeated tokens |
| `security.unicode` | B | HIGH | Invisible/bidi chars, homoglyph words |
| `security.yaml` | C | HIGH | Unknown frontmatter keys, malformed field values |
| `security.injection` | D | HIGH | Instruction override, identity override, safety bypass |
| `security.evaluator` | E | HIGH | Score manipulation, pass coercion, issue suppression |

Security checks are gate checks — they produce a BLOCK/SUS/ALLOW status rather than contributing to the numeric score. `sklab scan` aggregates all 5 checks into a single status.

**Files:** `checks/static/security.py`, `commands/scan.py`

### 2. `sklab optimize` — LLM-powered skill improvement

Evaluates a skill, sends failures to an LLM, and proposes SKILL.md improvements. Shows a colorized diff and score delta before applying.

```bash
sklab optimize ./my-skill              # Interactive: review diff, confirm apply
sklab optimize ./my-skill --auto       # Apply changes without confirmation
sklab optimize ./my-skill -m claude-sonnet-4-6  # Use a specific model
```

Uses the same Anthropic SDK and model resolution as `sklab generate` (`--model` flag > `SKLAB_MODEL` env var > `claude-haiku-4-5-20251001` default). Requires `ANTHROPIC_API_KEY`.

**Files:** `optimizer/optimizer.py`, `optimizer/optimize_skill.md`, `commands/optimize.py`

### 3. `sklab validate` → `sklab check`

Renamed for consistency with the CLI's check-oriented vocabulary. Behavior unchanged — runs all spec-required checks and exits 1 if any fail. A BLOCK from the security scan still fails the check.

**Files:** `commands/evaluate.py`

### 4. Project directory rename: `.skill-lab/` → `.sklab/`

Renamed the project-local artifact directory for consistency with the `sklab` CLI name.

| Before (v0.5.0) | After (v0.6.0) |
|------------------|----------------|
| `.skill-lab/tests/` | `.sklab/tests/` |
| `.skill-lab/traces/` | `.sklab/traces/` |

The global config directory (`~/.sklab/`) is unchanged.

**Files:** `core/constants.py`

### 5. Non-blocking telemetry sync

Moved the inline telemetry POST from synchronous to a daemon thread. Previously every command blocked for ~200ms (up to 2s on timeout) waiting for the HTTP response. Now the POST fires in a background thread and the CLI returns instantly. The existing retry mechanism handles any events that don't complete before process exit.

**Files:** `core/telemetry.py`

### 6. LLM configuration module

Centralized model defaults and pricing into a shared module used by both `generate` and `optimize`.

- Default model: `claude-haiku-4-5-20251001`
- Model resolution: `--model` flag > `SKLAB_MODEL` env var > default
- `GenerationUsage` class tracks token counts and cost per API call
- Pricing table covers Haiku 4.5, Sonnet 4.5, Sonnet 4.6, and Opus 4.6

**Files:** `core/llm.py`

### 7. CLI improvements

- **Hidden directory discovery:** `--all` flag now discovers skills inside `.claude/` and other hidden directories
- **Removed first-run repo scan:** Bare `sklab` no longer scans the repo on first run; shows the getting-started guide immediately
- **Trigger time estimation:** `sklab trigger` now shows estimated time remaining during test execution
- **Telemetry on all commands:** All commands now consistently record telemetry events
